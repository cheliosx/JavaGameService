## 技术选型建议（休闲游戏服务器）
- 框架：Spring Boot 3（HTTP/管理面，Tomcat 8080）+ Netty（长连接面，9000）双端口同一 JVM，共用业务 Service 层。二者不在同一抽象层，非二选一。
- 协议：HTTP 只做登录鉴权、首屏数据、支付回调、运营后台；游戏内实时协议与所有服务端推送全走 WebSocket binary frame + 自定义帧（4B 长度 + 4B cmdId + Protobuf payload）。HTTP 无"推送"，SSE 仅下行故排除。
- 关键约束：Netty ChannelHandler 内禁止阻塞调用；房间状态用单线程 Actor 串行化而非锁；断线重连（座位保留 + 快照补发）必须在脚手架层实现。
- 参考实现：ioGame（Spring Boot + Netty + 房间/广播封装）、jforgame。
- 演进：单进程 → Netty 网关与业务服拆分（房间一致性哈希）→ 网关/逻辑服集群。

### ioGame 21.28 实测关键结论（踩坑记录，避免下次重查）
1. WebSocket 握手路径是 **`/websocket`**，不是 `/`。写错会报 `HTTP/1.1 header parser received no bytes`。
2. WS 帧 = `DataCodecKit.encode(ExternalMessage)` 裸字节，**无 4 字节长度前缀**；TCP 才有（`ClientTcpExternalCodec` writeInt+writeBytes）。编解码器 `WebSocketExternalCodec` 可直接反查。
3. **`void` 返回值的 action 是单向协议，服务端不回任何包**（实测 noop 也无回包）。需要回执就必须返回消息体。
4. 基础类型返回值（boolean/int/String）会被 jprotobuf 包成 message（`[08 01]` 这种），自写客户端不能直接 `decode(..., Boolean.class)`，会报 "must has default constructor"。
5. **连接级 userId 绑定单向不可逆**：已绑定再 `setUserId` 返回 1005 BIND；`setUserId(0)` 无法解绑（`me` 依旧通过）。因此登录必须自己拦重复登录（已加 1006 ALREADY_LOGIN），登出语义只能是「吊销 token + 客户端断连」。
6. `FlowContext` 可直接作为 action 方法参数注入（`ParamInfo.isFlowContext()`），取 userId 用 `flowContext.getRequest().getHeadMetadata().getUserId()`，未登录为 0。
7. 登录接口必须在 `ExternalGlobalConfig.accessAuthenticationHook.addIgnoreAuthCmd(cmd, sub)` 里免鉴权，否则开启 verifyIdentity 后永远无法首登。
8. `MsgException extends RuntimeException`，`ErrorCode.xxx.assertTrue(cond)` 条件为 false 时抛，框架把 code 写进 responseStatus；**业务失败响应里 validMsg 为 null**，文案需客户端按码表本地化。
9. 启动不阻塞（`NettyRunOne.startup()` 立即返回），测试需自行轮询端口就绪；`IoGameGlobalConfig.brokerPort` 是可写静态字段，测试用它换端口。
10. 打包用 maven-assembly-plugin jar-with-dependencies，20MB，`java -jar` 直接启动，0.51s / 34MB。
